# APK Formats and Installation

## Format Overview

| Format | Extension | Structure | Install Method |
|--------|-----------|-----------|---------------|
| APK | `.apk` | Single monolithic package | Root `pm install` or PackageInstaller |
| APKM | `.apkm` | ZIP with split APKs | Extract ZIP → install splits via session API |
| XAPK | `.xapk` | ZIP with APKs + manifest.json + OBB | Same as APKM + copy OBB data |
| APKS | `.apks` | ZIP generated by bundletool | Same as APKM |
| AAB | `.aab` | Google's publishing format | Cannot be directly sideloaded |

## Installation Flow in HyperOS Updater

### Single APK (`.apk`)
1. Download to `filesDir/downloads/` (or `cacheDir/auto_update/` for auto-update)
2. Try Root: `su` + `pm install -S <size> -r -d -i com.android.vending` (stdin pipe, 120s timeout)
3. Try PackageInstaller.Session (unattended, best-effort)
4. Fallback: open system PackageInstaller via Intent

### Split Bundle (`.apkm`, `.xapk`, `.apks`)
1. Download to `filesDir/downloads/`
2. Extract ZIP → individual APK files
3. Try Root: `pm install -S <size> -r -d -i com.android.vending` per split
4. Fallback: PackageInstaller.Session with multi-split commit

### APKM Specifics
APKM is APKMirror's proprietary format. It is a ZIP containing:
- `base.apk` — the base application
- `split_config.arm64_v8a.apk` — architecture-specific code
- `split_config.xxxhdpi.apk` — density-specific resources
- `split_config.{language}.apk` — language resources
- ... up to 34+ split APKs

The bundle must be installed as a complete set — installing only `base.apk` fails.

### SELinux Constraints on HyperOS
HyperOS has strict SELinux policies. `system_server` (pm install) can only read files from
`/data/local/tmp/`. App private directories (`/data/data/...`) are inaccessible to shell UID.
The app works around this by piping APK content via stdin instead of passing file paths.
Root is the only method that can bypass these constraints reliably.
