# APK Formats and Installation

## Format Overview

| Format | Extension | Structure | Install Method |
|--------|-----------|-----------|---------------|
| APK | `.apk` | Single monolithic package | `ACTION_VIEW` + FileProvider → system installer |
| APKM | `.apkm` | ZIP with split APKs | Chooser "Instalar com…" → SAI-style installer |
| XAPK | `.xapk` | ZIP with APKs + manifest.json + OBB | Same as APKM |
| APKS | `.apks` | ZIP generated by bundletool | Same as APKM |
| AAB | `.aab` | Google's publishing format | Cannot be directly sideloaded |

## Installation Flow in HyperOS Updater (v1.5.0+)

### Single APK (`.apk`)
1. Download to `Downloads/HyperOSUpdater/`
2. `adjustArchiveType(file)` — detects bundles by ZIP content
3. `isWearOsApk(file)` — blocks watch APKs
4. `isLoneSplitApk(file)` — blocks lone config/DPI/ABI splits (v1.5.1)
5. `openInstallIntent(file)` → `ACTION_VIEW` with `application/vnd.android.package-archive` → opens system package installer

### Split Bundle (`.apkm`, `.xapk`, `.apks`)
1. Download to `Downloads/HyperOSUpdater/`
2. `adjustArchiveType(file)` — detects bundles by ZIP content, renames `.apk` → `.xapk` if needed
3. `isWearOsApk(file)` — scans inner APK manifests for watch marker
4. `openInstallIntent(file)` → `Intent.createChooser(ACTION_VIEW, "Instalar com…")` with `application/octet-stream` → user picks SAI or preferred split-APK installer (v1.5.2)

**The chooser is mandatory for bundles**: the MIUI stock installer silently captures bundle intents and fails with MISSING_SPLIT. Forcing the chooser lets the user select a SAI-style installer that handles split bundles correctly.

### APKM Specifics
APKM is APKMirror's proprietary format. It is a ZIP containing:
- `base.apk` — the base application
- `split_config.arm64_v8a.apk` — architecture-specific code
- `split_config.xxxhdpi.apk` — density-specific resources
- `split_config.{language}.apk` — language resources
- ... up to 34+ split APKs

The bundle must be installed as a complete set — installing only `base.apk` fails.

### Lone Split Detection (v1.5.1)
Some store pages list individual config/DPI/ABI splits alongside full bundles. If the user downloads one of these, it's a lone split — the system installer rejects it with `INSTALL_FAILED_MISSING_SPLIT`. The app detects this via `PackageInfo.splitNames` (non-null → it's a split, not a standalone base APK) and blocks install with a clear PT message: "Este arquivo é apenas uma parte (split) do app — baixe o pacote completo/bundle na página de variantes".

### Legacy Root/Session Methods (@Deprecated)
The old `su pm install` stdin-pipe and `PackageInstaller.Session` commit methods are `@Deprecated` on disk but removed from the dispatch chain. Root is now used only for full system logcat in `LogShareHelper`. The old methods are kept for reference — they may return if a future version re-introduces privileged install paths.
